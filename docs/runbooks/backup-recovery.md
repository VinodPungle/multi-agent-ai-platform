# Backup and recovery

What can be lost, what cannot be recovered, and what to do about each.

---

## 1. The honest summary

**The platform holds no durable data, so there is nothing to back up.**

That is not an achievement — it is a stage. It is true because conversation
memory is in-process and every other component is either stateless or
reproducible from source. It stops being true the moment persistent memory
arrives, and the recovery story has to be written before that, not after.

| What | Where it lives | Survives a restart? | Backed up? |
| --- | --- | --- | --- |
| Conversation history | Process memory | **No** | No — and cannot be |
| Prompts | Git, baked into the image | Yes | Git |
| Configuration | Bicep + azd environment | Yes | Git, except secrets |
| Secrets | Key Vault | Yes | Soft delete, 7 days |
| Container images | ACR | Yes | Rebuildable from a commit |
| Logs and traces | Log Analytics | Yes | Retention only, 30–90 days |
| Infrastructure | Bicep | Yes | Git |

---

## 2. Conversation memory is lost on restart

This is the one that will surprise a user rather than an operator.

Session memory is a bounded in-process store. A restart, a scale-to-zero
timeout, a deployment, or a crash all end every conversation in progress. The
chat UI says so — "held in server memory for this session" — which is honest but
easy to miss.

**It is also not shared between replicas.** With `minReplicas: 1` and a scale-out
under load, a user's second turn can land on a different instance and lose the
first. Reproducible, and not a bug to hunt.

**There is no recovery.** The data is gone. Do not spend time on it during an
incident.

**Mitigation, when it matters:** Milestone 08's memory work moves this to Redis
or Cosmos DB, at which point this section is replaced by a real backup
procedure. Until then, the correct operational stance is that conversations are
ephemeral and users should be told so.

## 3. Recovering each component

### Infrastructure

Fully reproducible from `infra/bicep/`.

```bash
azd provision
```

Idempotent: role assignments use deterministic GUIDs derived from scope,
principal and role, so a rerun updates rather than duplicates.

**What does not come back:**

- **A deleted resource group is gone.** Recreating it gives new resources with
  new names — a new Key Vault, a new registry, a new Foundry account. Any data
  those held is gone with them.
- **Key Vault has 7 days of soft delete.** Beyond that the name and its secrets
  are unrecoverable.

```bash
az keyvault list-deleted -o table
az keyvault recover --name <vault-name>
```

### Application

```bash
azd deploy
```

Images are tagged with the commit SHA, so any deployed revision is traceable to
a commit and rebuildable from it. If ACR itself were lost, every image can be
rebuilt — the registry is a cache of something Git already holds.

### Secrets

**Key Vault is the store; Git is not a backup of it.** Deliberately.

| Secret | If lost |
| --- | --- |
| Application Insights connection string | Regenerated by `azd provision` — it is read from the resource |
| Tavily API key | Regenerate at tavily.com and set it again. Not recoverable from anywhere |
| Azure credentials | None exist. `disableLocalAuth: true` |

There is no procedure for recovering the Tavily key because there cannot be one:
a secret that can be recovered from a backup you control is a secret an attacker
can recover the same way. Regenerating is the recovery.

### Telemetry

Logs and traces cannot be recovered beyond their retention window — 30 days in
development, 90 in production. If an investigation needs data older than that,
it does not exist.

**Export before it expires** if an incident may need long-lived evidence:

```bash
az monitor log-analytics query -w <workspace-id> \
  --analytics-query "AppTraces | where TimeGenerated > ago(7d)" \
  --output json > incident-evidence.json
```

## 4. Rebuilding an environment from nothing

Assumes the subscription exists and you have Owner on it.

```bash
az login
az account set --subscription <id>

azd env new <name>
azd env set AZURE_LOCATION centralus
azd env set TAVILY_API_KEY tvly-...        # if that environment uses Tavily
azd up
```

Expect 15–25 minutes; the model deployment is the slow part. Then verify:

```bash
curl -s "$(azd env get-value SERVICE_BACKEND_URI)/health"
```

**This has never been done.** `azd up` has not been run against these templates
— they compile and `az deployment sub validate` passes, which is weaker. The
first real rebuild should be expected to surface something, and it should be
performed as a drill *before* it is needed rather than during an incident.

That is the most valuable thing on this page: a recovery procedure nobody has
executed is a hypothesis.

## 5. What would need real backups

For when this section stops being hypothetical:

| Component | Arriving | What it would need |
| --- | --- | --- |
| Redis / Cosmos conversation memory | Milestone 08+ | Point-in-time restore; a documented RPO |
| Vector store | Milestone 09 | Snapshot plus a re-index procedure — re-embedding costs real money |
| Knowledge sources | Milestone 09 | Source of truth is upstream; the index is derived and rebuildable |
| User accounts and RBAC | Milestone 09 | Entra ID holds it; nothing to back up locally |

The pattern to keep: **derived data is rebuilt, not restored.** An index can be
recreated from its source; a conversation cannot be recreated from anything.
Only the second kind needs a backup, and it is the kind this platform does not
yet have.

## 6. Recovery objectives

Stated as measured or unmeasured, because an untested objective is a wish.

| | Target | Status |
| --- | --- | --- |
| RTO, application | Minutes — a revision traffic switch | Mechanism understood, undrilled |
| RTO, full environment | 15–25 minutes | **Never executed** |
| RPO, conversations | Zero — nothing is retained | By design, not by capability |
| RPO, everything else | Zero — reproducible from Git | Not drilled |

**No disaster recovery plan exists**, and multi-region is explicitly out of
scope. A region outage means an outage, until an environment is rebuilt
elsewhere by hand.
